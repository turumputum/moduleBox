# Art-Net в moduleBox

Устройство работает **только как приёмник** (Art-Net node, output port): принимает
ArtDMX и отвечает на ArtPoll. Генерация Art-Net в сеть не предусмотрена.

Сделано: системный сервис (сокет, обнаружение ноды пультом, приём ArtDMX в буферы
юниверсов, реестр подписок) и слот-модуль `artNetCrosslink`.
Модуля `artNetLeds` пока нет.

## Конфигурация

```ini
[ARTNET]
enable    = 1          ; 0 - протокол выключен, сокет не открывается
pollReply = 1          ; отвечать на ArtPoll
timeout   = 3000       ; мс тишины, после которых поток считается пропавшим
shortName = artnetBox  ; до 17 символов, пусто - deviceName
longName  = зал 2 сцена левая портальная ; до 63 символов, пусто - "moduleBox <deviceName>"
oem       = 0x00FF     ; OEM-код Art-Net
estaMan   = 0x7FF0     ; код производителя ESTA
dmxLog    = 0          ; 1 - печатать в лог первые 8 каналов каждого юниверса раз в секунду
```

Блок описан в манифесте: глава `ARTNET` в `configDescription`
([manifest.c](../components/manifest/manifest.c)), рядом с `SYSTEM`, `LAN`, `UDP`,
`OSC`, `MQTT`. Конфигуратор берёт список ключей, типы и значения по умолчанию
оттуда. Правка главы меняет содержимое `manifest-<VERSION>.json`, а `manifest.c`
перезаписывает файл только когда версионного файла нет - значит после правки
нужно удалить старый `manifest-<VERSION>.json` с тома (либо дождаться, когда
`VERSION` поднимут при выпуске).

По умолчанию `enable = 0`. Приёмник держит порт 6454 и разбирает **весь**
широковещательный трафик Art-Net сегмента, включая чужие юниверсы, — включать
без нужды не стоит.

**Списка юниверсов в `[ARTNET]` нет намеренно.** Обслуживаемые Port-Address
целиком складываются из `artnet_subscribe()`, который слот-модули вызывают на
старте своей задачи, читая собственную опцию `universe`. Отдельный ключ был бы
вторым источником правды и рано или поздно разошёлся бы с настройкой слотов:
пульт показывал бы порт, которого никто не слушает, или наоборот. Потолок —
`ARTNET_MAX_UNIVERSES` (8) разных юниверсов на устройство.

Если ни один слот не подписан, нода всё равно отвечает на ArtPoll и видна в
списке пульта — просто с нулём портов, назначить на неё нечего.

## Что устройство сообщает о себе

Ответ на ArtPoll — пакет **ArtPollReply**, 239 байт, широковещательно на порт 6454.
Именно из него пульт строит запись в списке устройств.

| Поле | Что показывает пульт | Откуда берётся | Настраивается |
|---|---|---|---|
| ShortName (18 б) | Имя ноды в списке устройств | `shortName`, иначе `deviceName` | да |
| LongName (64 б) | Описание в свойствах | `longName`, иначе `moduleBox <deviceName>` | да |
| NodeReport (64 б) | Строка состояния `#0001 [nnnn] <deviceName>` | счётчик ответов | нет |
| IP Address, BindIp | Адрес ноды | `esp_netif` активного интерфейса | через `[LAN]` / `[WIFI]` |
| MAC | Физический адрес | `esp_netif_get_mac()` | нет |
| VersInfoH/L | Версия прошивки, `3.70` → 3 и 70 | `VERSION` из `stateConfig.h` | нет |
| Oem | Модель ноды; пульты с базой OEM подставляют по нему картинку и число портов | `oem`, по умолчанию `0x00FF` (OemUnknown) | да |
| EstaMan | Код производителя ESTA | `estaMan`, по умолчанию `0x7FF0` (диапазон прототипов) | да |
| NumPorts, PortTypes, SwOut, NetSwitch, SubSwitch | Сколько портов и на каких Port-Address | реестр юниверсов | через `universes` и подписки модулей |
| GoodOutput | Индикатор «в порт идут данные» | `artnet_is_alive()` по `timeout` | косвенно |
| Style | Класс устройства, `0x00` StNode | константа | нет |
| Status1 / Status2 / Status3 | Режим индикаторов, кто задаёт адреса портов, DHCP, 15-битные Port-Address | вычисляется | нет |
| BindIndex | Номер пакета, если портов больше четырёх | вычисляется | нет |

Своего OEM-кода у проекта нет. `0x00FF` (OemUnknown) корректен и понятен любому
пульту; настоящий код выдаёт Artistic Licence, код ESTA — сама ESTA. Пока их нет,
`0x7FF0` из диапазона прототипов — честный вариант.

**Куда уходит ответ.** По протоколу ArtPollReply широковещательный, адрес
считается от IP и маски ноды. Если у пульта маска уже, чем у ноды (нода получила
по DHCP /16, пульт настроен на /24), его стек отбросит такой пакет как чужой —
поэтому копия ответа уходит ещё и юникастом тому, кто прислал ArtPoll. Пассивные
мониторы, слушающие чужие опросы, при этом продолжают видеть бродкаст.

**Ограничение протокола:** в одном ArtPollReply помещается 4 порта, и все они
обязаны иметь общие старшие 11 бит Port-Address (Net и Sub-Net). Юниверсы, которые
в это не укладываются, рассылаются отдельными пакетами с возрастающим BindIndex —
пульт склеивает их в одно устройство по общему IP и BindIp.

**Нумерация:** `universe` в конфиге — это Art-Net Port-Address, 0-based. Многие
пульты показывают его как «Universe 1». Юниверс 0 в конфиге = первый юниверс в
интерфейсе пульта.

## Проверка

```
python pyTest/artnetTest.py poll                 ; разослать ArtPoll и распечатать все поля ответов
python pyTest/artnetTest.py dmx 192.168.88.33 0 10   ; 10 секунд ArtDMX 44 Гц в юниверс 0
```

`poll` печатает содержимое ArtPollReply целиком — этим удобно проверять, что имена
и список портов доехали такими, как задумано. Приём кадров смотреть с `dmxLog = 1`:
в лог раз в секунду уходит `u0 len:512 seq:37 ch1-8: ...`.

В QLC+ нода появляется в *Inputs/Outputs → ArtNet*. В SyncD Art-Net Monitor — в
списке нод после нажатия Poll.

Порт 6454 открывается только после подъёма сетевого интерфейса; реестр юниверсов
готов раньше, до старта слотов, — иначе слот-модули не нашли бы сервис при подписке.

В логе при исправной работе видно:

```
I artNet: registry ready: 'moduleBox' / 'moduleBox test node', 1 universe(s) from config
I artNet: listening on UDP 6454
I artNet: ArtPollReply -> 192.168.255.255, ports:1
I artNet: universe 0: stream started, 512 channels
```

Если ни одной строки с тегом `artNet` нет — проверьте `logLevel` в `[SYSTEM]`
(нужен `info` или выше) и что тег `artNet` присутствует в списке
`esp_log_level_set()` в [main.c](../main/main.c). Список белый: `*` выставлен в
`ESP_LOG_ERROR`, и тег, которого в перечислении нет, молчит полностью.

## Модуль artNetCrosslink

Следит за диапазоном DMX-каналов и публикует их значения событиями moduleBox.
Пинов не занимает, ставится в любой слот 0-9, включая виртуальные.

```ini
[SLOT_7]
mode = artNetCrosslink
options = universe:3, startAddress:1, numOfChannels:4, chWidth:word, deadBand:64, minInterval:40
crosslink = artNetCrosslink_7/event/ch_0/val -> stepper_2/action/moveToAbs:@
```

| Опция | Тип | По умолчанию | Диапазон | Смысл |
|---|---|---|---|---|
| `universe` | int | 0 | 0-32767 | Art-Net Port-Address, 0-based |
| `startAddress` | int | 1 | 1-512 | DMX-адрес, соответствующий `ch_0` |
| `numOfChannels` | int | 8 | 1-16 | Сколько значений отслеживать |
| `chWidth` | enum | `byte` | `byte` / `word` | Разрядность одного значения |
| `wordOrder` | enum | `hiLo` | `hiLo` / `loHi` | Порядок байтов при `word` |
| `deadBand` | int | 2 | 0-4096 | Минимальное изменение для события; для `word` ставьте 64 |
| `minInterval` | int | 30 | 0-10000 | Минимальный интервал между событиями канала, мс |
| `sendOnStart` | flag | off | — | Выдать все значения по первому кадру |
| `sendOnTimeout` | flag | off | — | Повторить последние значения при пропадании потока |
| `disableOnStart` | flag | off | — | Оставить модуль спящим до `action/enable 1` |

События:

```
artNetCrosslink_7/event/ch_0/val    128     значение канала
artNetCrosslink_7/event/stream      1       поток по юниверсу жив, 0 - таймаут
artNetCrosslink_7/event/enable      1       модуль активен
```

Действия: `action/enable 0|1`.

**Потолок 16 каналов на слот** — не память, а таблица отчётов:
`MAX_NUM_OF_STDREPORTS` равен 100 на всё устройство и делится между всеми слотами.
Плюс подтопик каждого канала обязан быть строковым литералом в коде, иначе
манифест получит вместо топика имя переменной. Заявленные в ТЗ 128 каналов
в эту таблицу не помещаются в принципе.

**При `chWidth = word`** одно значение занимает два соседних DMX-канала:
`ch_0` → `startAddress` (старший) и `startAddress+1` (младший) при `hiLo`.
`hiLo` — стандартная DMX-конвенция coarse/fine, её используют QLC+ и большинство
пультов.

**Дедбенд считается от последнего отправленного значения**, а не от предыдущего
кадра, — медленный увод фейдера не накапливается незамеченным. `minInterval`
режет темп: художник ведёт фейдер 0→255 за три секунды, это ~130 событий при
44 Гц, а очередь команд принимающего модуля — 15 элементов.

**При потере потока** модуль публикует `event/stream 0` и сбрасывает базу
дедбенда: возврат потока считается новым стартом, политика `sendOnStart`
отрабатывает заново. Парковать исполнительные механизмы на пропадание сигнала
следует через `event/stream`, а не через значения каналов — так решение остаётся
явным и не зависит от того, какое значение стояло в кадре последним.

**Если `[ARTNET] enable = 0`,** модуль пишет ошибку в лог с номером слота и
снимает свою задачу, не занимая очередь команд. Остальное устройство работает
штатно.

## Порядок инициализации

```
app_main()
  loadConfig()
  init_artNet()          <- реестр юниверсов и имена ноды, сокета ещё нет
  init_slots()           <- artNetCrosslink подписывается на свой universe
  ...
  network_services_task()
    start_artNet_task()  <- сокет 6454, приём, ArtPollReply
```

Реестр обязан быть готов до `init_slots()`, иначе подписка не найдёт сервис.
Сокет, наоборот, открывается только после подъёма интерфейса — к этому моменту
все подписки уже на месте, и первый же ArtPollReply перечисляет реальные порты.
