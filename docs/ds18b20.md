# ds18b20

Термометры DS18B20 на шине 1-Wire. Линия данных — **нулевой пин слота**
(`SLOTS_PIN_MAP[slot][0]`). На одной шине до четырёх датчиков.

```ini
[SLOT_2]
mode = ds18b20
options = deadBand:200, periodic:30, threshold:25000
crosslink = temp_2/event/ch_0/threshold:@ -> out_0/action/setVal:@
```

**Температура публикуется в милиградусах Цельсия целым числом:** `24500` это
24,5 °C. Так же задаются `deadBand` и `threshold`. Это следствие общего правила
проекта — считать в целых, дробное брать в крайнем случае, см-
[COMPONENT_SKILL раздел 7-5](../COMPONENT_SKILL.md). Если получателю нужны
градусы, переведите арифметикой кросслинка: `@/1000`.

## Опции

| Опция | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `deadBand` | int, мК | 100 | Минимальное изменение для публикации |
| `threshold` | int, мК | выключен | Порог срабатывания |
| `stateInverse` | flag | off | Инверсия состояния порога |
| `silent` | flag | off | Не публиковать температуру, только порог |
| `periodic` | int, с | 0 | Публиковать каждые N секунд; 0 — только при изменении |
| `resolution` | int, бит | 12 | 9–12; влияет на время преобразования |
| `defaultState` | int | 1 | 0 — модуль спит до `action/enable 1` |

## События и команды

```
temp_2/event/ch_0/temperature   24500   температура датчика 0 в милиградусах
temp_2/event/ch_0/threshold     1       порог пройден
temp_2/event/enable             1       состояние модуля
temp_2/action/enable            0|1     спать / работать
```

Каналы `ch_0`…`ch_3` нумеруются по возрастанию адреса ROM — порядок не зависит
от физического расположения датчиков на шлейфе, но **стабилен между
перезагрузками**. Адрес каждого датчика печатается при старте, по нему и надо
сопоставлять каналы с реальными точками измерения:

```
I ONE_WIRE: [temp_2] ch_0 address 28FF641F8A3C1B04
I ONE_WIRE: [temp_2] ch_1 address 28AA0C5B1D1401C7
I ONE_WIRE: [temp_2] ready: 2 sensor(s), 12 bit, deadBand 200 mC, periodic 30 s
I ONE_WIRE: [temp_2] poll period 30000 ms
```

Дедбенд считается от последнего **опубликованного** значения, поэтому медленный
дрейф не накапливается незамеченным.

## Время опроса

Драйвер ждёт преобразование внутри вызова, датчики опрашиваются по очереди —
цикл растёт линейно с их числом:

| Разрядность | Шаг | Один датчик | Четыре датчика |
|---|---|---|---|
| 12 бит | 0.0625 °C | 0.8 с | 3.4 с |
| 11 бит | 0.125 °C | 0.4 с | 1.8 с |
| 10 бит | 0.25 °C | 0.2 с | 1.0 с |
| 9 бит | 0.5 °C | 0.1 с | 0.6 с |

Если `periodic` меньше времени полного прохода, модуль пишет ошибку в лог и
берёт время прохода — иначе `vTaskDelayUntil` выродился бы в цикл без пауз.

Шина занимает **канал RMT** (приём и передача). Их у ESP32-S3 по четыре, и те же
каналы расходуют адресные ленты (`button_smartLed`, `artNetLeds`). При нехватке
модуль пишет ошибку и снимает свою задачу, не роняя устройство.

## Отличия от прежней версии модуля

Режим `ds18b20` существовал и раньше, но не попадал в манифест и публиковал
события в обход конституции. Что изменилось:

| Было | Стало |
|---|---|
| `<dev>/temp_2:24.5` | `<dev>/temp_2/event/ch_0/temperature`, значение `24500` |
| `<dev>/temp_2/state:1` | `<dev>/temp_2/event/ch_0/threshold` |
| только первый найденный датчик | до четырёх, каждый своим каналом |
| нет команд | `action/enable` |
| нет в манифесте | режим и все опции видны конфигуратору |

**Существующие правила crosslink на старые топики придётся переписать.** И
учесть смену единиц: значение теперь в милиградусах, то есть в тысячу раз
больше прежнего. `deadBand:0.2` в опциях надо заменить на `deadBand:200`,
`threshold:25` на `threshold:25000` — иначе дедбенд станет неощутимым, а порог
сработает на любой температуре.

Порог по умолчанию теперь **выключен явно**, а не нулём: ноль милиградусов это
законные 0 °C, и раньше порог на замерзание задать было нельзя.

Попутно исправлено: `deadBand` пропускался через целочисленный `abs()` и любое
значение меньше единицы превращалось в ноль; `ESP_ERROR_CHECK` на создании шины
ронял всё устройство в панику, если пин или канал RMT заняты.
