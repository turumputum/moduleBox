# ТЗ: модуль artNetLed

Приём Art-Net (ArtDMX) и вывод на адресную ленту WS2812 и родственные.
Слот-модуль поверх готового системного сервиса Art-Net.

Документ — задание на реализацию. Протокольная часть подчинена
[CONSTITUTION.md](../CONSTITUTION.md), оформление кода — [COMPONENT_SKILL.md](../COMPONENT_SKILL.md).

---

## 1. Назначение

Модуль превращает слот в выходной порт Art-Net-ноды: берёт DMX-каналы из одного
или нескольких юниверсов и раскладывает их по пикселям ленты, подключённой к
выходу слота. Своей анимации у модуля нет — картинку целиком задаёт пульт.

Модуль ставится в несколько слотов одновременно: у каждого своя лента, свой
универс и свой стартовый адрес.

## 2. Что уже готово и что придётся дописать

### Готово — трогать не нужно

Сервис Art-Net, [artNet.h](../components/artNet/include/artNet.h):

| Функция | Что даёт модулю |
|---|---|
| `artnet_is_enabled()` | протокол включён в `[ARTNET]` конфига |
| `artnet_subscribe(universe, slot, task)` | буфер `artnet_universe_t` на 512 байт с мьютексом; задача получает `xTaskNotifyGive()` на каждый принятый кадр |
| `artnet_is_alive(u)` | по юниверсу идут кадры с учётом `artNet_timeout` |
| `artnet_unsubscribe(universe, slot)` | снятие подписки |

Подписка на один и тот же юниверс из нескольких слотов допустима — буфер общий,
потолок `ARTNET_MAX_SUBS` = 4 подписчика. Разных юниверсов на устройство —
`ARTNET_MAX_UNIVERSES` = 8.

### Готово частично — потребует доработки

Транспорт ленты, [led_types.c](../components/buttonLeds/led_types.c):

| Что есть | Ограничение | Что нужно |
|---|---|---|
| `rmt_createAndSend()` | пересоздаёт RMT-канал на каждый кадр под глобальным семафором | годится как есть, но см. §6.3 про частоту |
| `led_strip_set_pixel()` | жёстко GRB, ровно 3 байта на пиксель | нужна запись произвольного порядка и 3-5 байт |
| кодер RMT | тайминги зашиты под WS2812 (T0H 0.3 мкс, T1H 0.9 мкс) | параметризация под WS2811 (400 кГц), если он в объёме |
| `rmt_semaphore` | создаётся лениво каждым LED-модулем: `if (rmt_semaphore == NULL) rmt_semaphore = xSemaphoreCreateCounting(1, 1);` | artNetLed обязан сделать то же самое в своей start-функции |

Писать пиксель универсально предлагается локальной функцией внутри модуля, не
ломая `led_strip_set_pixel()` — её используют шесть существующих модулей.

## 3. Конфигурация слота

```ini
[SLOT_4]
mode = artNetLed
options = numOfLed:300, universe:0, startAddress:1, colorOrder:grb, maxBright:200
crosslink = empty
```

| Опция | Тип | По умолчанию | Диапазон | Смысл |
|---|---|---|---|---|
| `numOfLed` | int | 60 | 1-1024 | Количество пикселей в ленте |
| `ledType` | enum | `ws2812` | `ws2812` `sk6812` `ws2811` | Чип ленты, задаёт тайминги RMT |
| `colorOrder` | enum | `grb` | см. ниже | Порядок байт в ленте и число каналов на пиксель |
| `universe` | int | 0 | 0-32767 | Art-Net Port-Address первого юниверса, отсчёт от нуля |
| `startAddress` | int | 1 | 1-512 | DMX-адрес первого канала первого пикселя, отсчёт от единицы |
| `maxBright` | int | 255 | 0-255 | Общий потолок яркости, значения из DMX масштабируются |
| `RGBcolor` | rgb | `255 255 255` | 0-255 каждый | Цвет тест-заливки по команде `action/testLed 1` |
| `refreshRate` | int | 40 | 1-100 | Предел частоты выдачи в ленту, Гц |
| `disableOnStart` | flag | выкл | — | Оставить модуль спящим до `action/enable 1` |
| `blackOnTimeout` | flag | выкл | — | Гасить ленту при пропадании потока, иначе держать последний кадр |

`refreshRate` ограничен сотней сознательно — проектное решение по всем модулям.

### colorOrder

Одна буква — один канал. Число букв задаёт и байт на пиксель, и каналов DMX
на пиксель.

| Значение | Каналов | Комментарий |
|---|---|---|
| `rgb` | 3 | |
| `rbg` `grb` `gbr` `brg` `bgr` | 3 | `grb` — обычная WS2812 |
| `rgbw` `grbw` | 4 | SK6812 RGBW |
| `rgbww` `grbww` | 5 | Тёплый и холодный белый отдельными каналами |

**Со стороны DMX порядок всегда канонический** — R, G, B, затем W, затем второй
W. Пульт патчит пиксель как обычный RGB или RGBW прибор и ничего не знает про
разводку ленты. `colorOrder` описывает только то, в каком порядке байты уходят
в ленту: это свойство железа, а не пульта.

## 4. Раскладка DMX по пикселям

`bpp` — каналов на пиксель, равно числу букв в `colorOrder`.

### Ёмкость юниверса

```
первый юниверс:    floor((512 - (startAddress - 1)) / bpp)  пикселей
каждый следующий:  floor(512 / bpp)                         пикселей
```

`startAddress` действует **только на первый юниверс**, последующие начинаются с
канала 1. Пиксель не разрывается через границу юниверса: хвост в 1-2 канала
остаётся неиспользованным. Так патчит большинство пультов.

| bpp | Пикселей в юниверсе при startAddress 1 | Неиспользованных каналов |
|---|---|---|
| 3 | 170 | 2 |
| 4 | 128 | 0 |
| 5 | 102 | 2 |

### Сколько юниверсов занимает лента

```
firstCap = floor((512 - (startAddress - 1)) / bpp)
nextCap  = floor(512 / bpp)

numOfLed <= firstCap  ->  1 юниверс
иначе                 ->  1 + ceil((numOfLed - firstCap) / nextCap)
```

Модуль подписывается на `universe`, `universe + 1`, ... подряд, без пропусков.

Пример: `numOfLed:300, universe:0, startAddress:1, colorOrder:grb`

```
universe 0 : каналы 1..510   -> пиксели 0..169
universe 1 : каналы 1..390   -> пиксели 170..299
```

### Проверки при конфигурации

1. Требуемое число юниверсов превышает свободные в реестре (`ARTNET_MAX_UNIVERSES` = 8 на устройство, их делят все слоты) — `numOfLed` урезается до того, что поместилось; в лог `ESP_LOGE` и `mblog(E, ...)`. Модуль работает укороченной лентой, а не падает.
2. `artnet_subscribe()` вернул `NULL` хотя бы на первом юниверсе — фатальная ошибка, см. §7.
3. `startAddress` такой, что в первом юниверсе не помещается ни одного пикселя — `startAddress` принудительно в 1, в лог предупреждение.

## 5. Топики

Базовый топик: `<deviceName>/artNetLed_<slot>`. Заполняются обе таблицы,
`action_topic_list` и `trigger_topic_list`.

### События

| Топик | Тип | Когда |
|---|---|---|
| `event/enable` | int 0/1 | Один раз после старта и на каждую команду `action/enable` |
| `event/stream` | int 0/1 | Смена состояния потока: 1 — кадры идут, 0 — таймаут |
| `event/error` | string | Фатальная ошибка старта, см. §7 |

`event/stream` — то же имя, что у `artNetCrosslink`, намеренно: подписка
`<dev>/+/event/stream` показывает состояние Art-Net по всем слотам сразу.

Состояние потока считается по **первому** юниверсу ленты. Если лента занимает
несколько юниверсов, поток считается живым, пока жив первый: пульт, который
перестал слать один универс из трёх, — это не пропадание потока, а дыра в
картинке, и различать их в булевом отчёте нечем.

### Команды

| Топик | Параметры | Действие |
|---|---|---|
| `action/enable` | int 0/1 | Проснуться или уснуть |
| `action/testLed` | int 0/1 | 1 — залить ленту цветом `RGBcolor`, 0 — вернуться к Art-Net |

`action/enable 0` гасит ленту и перестаёт разбирать кадры; подписка на юниверсы
сохраняется. `action/enable 1` возвращает вывод с ближайшего кадра.

`action/testLed` — один `PARAMT_int`. Цвет заливки берётся из опции `RGBcolor`,
а не из тела команды: тест проверяет разводку и адресацию, а не подбирает
оттенок, и одинаковая пара `1`/`0` у всех переключаемых команд читается легче.

## 6. Поведение

### 6.1 Старт задачи

Порядок важен: конфигурация идёт **до** проверок, иначе некому будет
опубликовать `event/error` — топики и отчёты ещё не зарегистрированы.

```
1. command_queue = xQueueCreate(15, ...)
2. configure_artNetLed()      // топики, опции, регистрация команд и отчётов
3. rmt_semaphore, если NULL   // как в остальных LED-модулях
4. проверка artnet_is_enabled()
5. выделение буфера пикселей
6. подъём RMT
7. artnet_subscribe() по всем нужным юниверсам
8. waitForWorkPermit(slot_num)
9. stdreport_enable(slot_num, active_state)
10. рабочий цикл
```

Шаги 4-7 при неудаче — по §7.

### 6.2 Буфер пикселей

`numOfLed * bpp` байт, сначала `heap_caps_calloc(..., MALLOC_CAP_SPIRAM)`, при
неудаче обычный `calloc` — как в `button_smartLed`. Не получилось ни так, ни
так — фатальная ошибка.

### 6.3 Рабочий цикл

```
ulTaskNotifyTake(pdTRUE, pdMS_TO_TICKS(IDLE_TICK_MS));   // IDLE_TICK_MS = 100
разбор команд, пока stdcommand_receive() != -1
проверка artnet_is_alive() -> смена event/stream
если не active_state или тест-режим -> дальше не идём
если с прошлой выдачи прошло меньше 1000/refreshRate мс -> дальше не идём
сборка кадра из буферов юниверсов -> выдача в ленту
```

**Почему выдача ограничена `refreshRate`, а не идёт на каждый кадр.** Кадры
Art-Net приходят с частотой пульта, обычно 40-44 Гц, и `pdTRUE` в
`ulTaskNotifyTake` уже схлопывает пачку в один проход. Но выдача в ленту стоит
дорого: бит WS2812 — 1.25 мкс, пиксель — 30 мкс.

| Пикселей | Время выдачи, bpp 3 | Потолок частоты |
|---|---|---|
| 170 | 5.1 мс | ~190 Гц |
| 340 | 10.2 мс | ~95 Гц |
| 680 | 20.4 мс | ~48 Гц |
| 1024 | 30.7 мс | ~32 Гц |

Плюс `rmt_createAndSend()` на каждый кадр создаёт и удаляет RMT-канал под
глобальным семафором, общим со всеми LED-модулями устройства. Без ограничения
длинная лента заняла бы семафор почти целиком и заморозила подсветку кнопок в
соседних слотах.

### 6.4 Сборка кадра

Мьютекс юниверса держится **только на копировании** нужного куска в локальное
окно, как в `artNetCrosslink`. Разбор, масштабирование яркости и раскладка по
порядку цветов — уже вне мьютекса.

Юниверсы копируются по очереди, каждый под своим мьютексом: кадр, собранный из
двух соседних приёмов, для ленты не страшен — расхождение на один кадр глазом
не видно.

Кадр короче ожидаемого окна — хвост считается нулями, а не мусором.

Яркость: `out = dmx * maxBright / 255`, целочисленно.

### 6.5 Таймаут потока

`artnet_is_alive()` вернул false:

- публикуется `event/stream 0`
- при `blackOnTimeout` лента гасится одной выдачей, дальше выдача не повторяется
- без флага на ленте остаётся последний кадр

Поток вернулся — `event/stream 1`, вывод возобновляется с ближайшего кадра.

### 6.6 Тест-режим

`action/testLed 1` заливает всю ленту цветом из опции `RGBcolor` и **перекрывает
Art-Net**: пока тест активен, кадры продолжают разбираться и `event/stream`
живёт, но в ленту выдаётся заливка.

`action/testLed 0` снимает режим, вывод возвращается к Art-Net с ближайшего
кадра. `action/enable 0` тоже снимает тест — уснувший модуль просыпается в
обычном режиме, а не в тестовом.

Заливка выдаётся один раз на входе в режим, а не каждый период: картинка
статична, гонять RMT вхолостую незачем. Повторная `action/testLed 1` при уже
включённом тесте выдаёт заливку заново — это штатный способ обновить цвет, если
`RGBcolor` поменяли перезагрузкой конфига.

Тест-заливка проходит через `maxBright` так же, как обычный кадр: иначе
проверка на полной яркости слепит и не показывает реальную настройку.

## 7. Ошибки

Общее правило: в лог через `ESP_LOGE` **и** в `mblog(E, ...)` на SD, плюс
`event/error` строкой. После этого задача удаляется — `vTaskDelete(NULL)`,
единообразно с `artNetCrosslink`.

Публикация до удаления работает: `stdreport_s()` кладёт сообщение в
`reporter_queue`, а публикует отдельная задача репортера. Если MQTT на этот
момент ещё не поднялся, репортер буферизует сообщение и отдаст его при
подключении.

| Значение `event/error` | Причина |
|---|---|
| `noArtNet` | Протокол выключен в `[ARTNET]`, слушать нечего |
| `noUniverse` | `artnet_subscribe()` вернул NULL — реестр юниверсов полон |
| `noMemory` | Не выделился буфер пикселей |
| `noPeriph` | Не поднялся RMT-канал или кодер |

Перед удалением задачи публикуется ещё и `event/enable 0` — подписчик на
`<dev>/+/event/enable` увидит, что слот не работает, не разбирая коды ошибок.

Ошибки, которые **не** фатальны и лечатся урезанием (см. §4): нехватка
юниверсов под всю длину, негодный `startAddress`. Они пишутся в лог и mblog,
но модуль продолжает работу.

## 10. Решения, принятые по умолчанию

Ниже то, что не обсуждалось явно и выбрано по аналогии с существующим кодом.
Каждое можно поменять до начала реализации.

**1. `event/stream` считается по первому юниверсу.** Альтернатива — отдельный
отчёт на каждый универс, но это множит сущности и упирается в литеральные
подтопики.

**2. Цвет тест-заливки — белый по умолчанию.** Команда переключается парой
`1`/`0`, цвет живёт в опции `RGBcolor`. Умолчание белое, а не синее `0 0 255`,
как в кнопочных модулях: белый разом показывает все три канала пикселя и сразу
выявляет перепутанный `colorOrder`. Имя опции оставлено общим с остальными
LED-модулями намеренно — конфигуратор и пользователь уже знают его.

Забытый `testLed 1` перекрывает Art-Net до явного `testLed 0` или `enable 0`.
Автоматического выхода по таймеру нет; если он понадобится, добавляется опцией
`testTimeout` без изменения протокола.

**3. `blackOnTimeout` выключен по умолчанию.** Пропал пульт — на сцене остаётся
последний кадр, а не темнота. Для инсталляций это обычно правильнее.

**4. `ledType` в первом этапе может быть заглушкой.** WS2812 и SK6812 работают
на одних таймингах, разница только в `colorOrder`. WS2811 на 400 кГц требует
параметризации кодера в `led_types.c` — если он не нужен сейчас, опцию оставить,
а значение `ws2811` отклонять с записью в лог.

**5. Порядок цветов со стороны DMX фиксирован** — R G B W W. Пульт патчит
стандартный прибор, `colorOrder` описывает только разводку ленты.
