# Арифметика значения в crosslink

Правило crosslink имеет вид:

```
<событие>[:<фильтр>] -> <действие>[:<значение>]
```

В позиции значения `@` означает значение события. К нему можно применить цепочку
арифметических операций.

```ini
; DMX-канал 0-255 в ширину импульса сервы 1000-1969 мкс
crosslink = artNetCrosslink_5/event/ch_0/val:@ -> servo_2/action/setPulse:@*3.8+1000

; 16-битный фейдер 0-65535 в позицию шаговика 0-4000 шагов
crosslink = artNetCrosslink_7/event/ch_0/val:@ -> stepper_1/action/moveToAbs:@/16.38

; реверс направления
crosslink = artNetCrosslink_7/event/ch_5/val:@ -> stepper_3/action/moveToRel:@*-1
```

## Грамматика

```
<value> ::= ( '@' | <num> ) { <op> <num> }
<op>    ::= '*' | '/' | '+' | '-'
<num>   ::= ['-'] цифры [ '.' цифры ]
```

- **Операции применяются слева направо, без приоритета умножения.** `@+10*2`
  это `(v+10)*2`, а не `v+20`. Типовая запись «масштаб, потом смещение»
  (`@*3.8+1000`) в обоих прочтениях совпадает, а для конфигурационного файла
  предсказуемость важнее школьной привычки.
- До четырёх операций в цепочке (`XL_MAX_OPS`).
- Пробелы вокруг операторов допустимы: `@ * 3.8 + 1000`.
- Разделитель дробной части — только точка. Запятая занята под разделитель
  правил crosslink.
- Экспоненциальная запись запрещена: `@*1e3` — ошибка разбора, а не множитель
  1000.
- Деление на ноль отвергается при разборе.

## Тип результата

**Результат всегда округляется до целого**, к ближайшему, половина от нуля:
`@/4` от 10 даёт 3, от -10 даёт -3.

Причина в том, что кросслинкер не знает тип параметра команды-получателя.
Проверка типов в `stdcommand` принимает целое и для `PARAMT_int`, и для
`PARAMT_float`, а дробное — только для `PARAMT_float`. Целое на выходе означает,
что правило никогда не отвалится по несовпадению типа. Дробные значения на
выходе выражения сегодня получить нельзя.

## Что считается литералом

| Значение действия | Что уйдёт получателю |
|---|---|
| `@` | значение события как есть |
| `@*2.4` | значение события, умноженное на 2-4, округлённое |
| `5` | `5` — литерал, значение события игнорируется |
| `flash` | `flash` — строковый литерал |
| (значения нет) | значение события как есть |

> **Изменение поведения.** Раньше при триггере с `@` значение действия
> затиралось значением события **всегда** — даже если в правиле был явно
> написан литерал. То есть `... :@ -> led_1/action/setMode:flash` отправлял
> в `setMode` число из события. Теперь литерал уходит как написан.

## Ошибки

Нераспознанное выражение пишет в лог `crosslink: bad expression '<текст>' (err N)`
и передаёт значение события без изменений. Коды: `-1` пусто, `-2` неожиданный
символ, `-3` деление на ноль, `-4` цепочка длиннее четырёх операций.
